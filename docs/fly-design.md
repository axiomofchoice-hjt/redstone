# 飞行器模块设计

独立的第二套玩法：在格子地图上拼装由活塞、粘液块、红石块组成的机器，让它自己飞起来抵达终点。
**不改动现有 `src/game/sim.ts` 与关卡数据**，新开 `src/fly/`。

## 1. 视角

MC 的飞行器本身不受重力影响（只有沙砾这类方块会掉），所以「俯视」和「侧视」在规则上没有任何区别，
差别只在画法和关卡布局：

| | 俯视 | 侧视 |
| --- | --- | --- |
| 画法 | 从上方看，四方向等价 | 横向长条，竖直方向是"上下" |
| 关卡 | 整张地图都能用，适合绕障、迷宫 | 一般做成横向长廊 |
| 手机操作 | 拖动平移最自然 | 需要频繁横向滚动 |

结论：**俯视、无重力**。将来如果要加"掉落"才需要重新讨论。

## 2. 从 MC 保留 / 砍掉

保留：

- 活塞推动前方沿一条线最多 12 个方块
- 粘液块把相邻的可动块一起带走（推力组的连通规则）
- 粘性活塞缩回时拉回前方的方块，粘液块连带整组
- 红石块是可以被推动的电源
- **活塞推不动自己**：推力组里包含这台活塞自己时，这一推无效

砍掉：

- 观察者、BUD、方块更新顺序、准连接（QC）
- 0-tick 脉冲、TNT dupe 这类依赖 bug 的玩法
- 蜂蜜块（先用粘液块一种，需要再加）

## 3. 数据模型

```ts
export type FlyPartType = 'block' | 'slime' | 'piston' | 'stickyPiston' | 'redstone'

export interface FlyPart {
  type: FlyPartType
  /** 只有活塞有朝向 */
  dir?: Dir
  /** 关卡预置、玩家不能删 */
  locked?: boolean
}

export interface FlyLevel {
  id: string
  no: number
  name: string
  cols: number
  rows: number
  /** 静态地形：true = 墙，不可通过也不可推动 */
  walls: boolean[]
  /** 初始机器与预置零件，按行优先铺平 */
  cells: (FlyPart | null)[]
  /** 终点：机器所有零件都落在这些格子里算过关 */
  goal: number[]
  /** 这关可用的零件，不写表示全部 */
  tools?: FlyPartType[]
  /** 参考解（可选），和电路关卡一样用字符画或导出的地图 */
  solution?: { cells: (FlyPart | null)[] }
}
```

## 4. 运行模型

状态就是一张格子表 + 每个活塞的伸出状态：

```ts
interface FlyState {
  cells: (FlyPart | null)[]
  /** 活塞已伸出：机身占 i，头占 i + dir */
  extended: Set<number>
  tick: number
}
```

**伸出时活塞占两格**（机身 + 头）。这一点很重要：

- 伸出的活塞是"不可推动"的，这正是飞行器能卡住、能当刹车的原因
- 缩回时先把头让出来，粘性活塞才有地方把方块拉回来

## 5. 每个 tick 的执行顺序

为了让玩家能预测，固定成两阶段：**先全部计划，再统一应用**。

1. **算电**：红石块是电源；电源沿着粘液块传导（粘液块能导电）。咬住电源的活塞算通电。
2. **生成意图**：每个活塞对比"当前伸出状态"和"是否通电"，得到 `推` / `拉` / `不动`。
3. **计划**：按格下标从小到大，为每个 `推` / `拉` 计算推力组和目的地。
   - 收集推力组：从前一格开始 BFS。当前格是粘液块时，才把四邻接的可动块并进来；不是粘液块就停止扩张。
   - 组里出现墙 / 出界 / 已伸出的活塞 / 推力组本身 → 这一推无效。
   - 组大小 > 12 → 无效。
   - **组里出现这台活塞自己 → 无效**（推不动自己）。
   - 目的地被组外的零件占着 → 无效。
4. **冲突**：两个活塞要动同一批格子，或者目的地重叠 → 双方都取消（对应 MC 里的"卡住"）。取消时记录一个 `stalled` 标记，界面可以提示"卡住了"。
5. **应用**：整组平移，更新 `extended`，`tick++`。

这样同一份状态跑两次顺序一致，测试好写；不同的活塞顺序也不会互相影响结果（冲突一律取消）。

## 6. 电与自持

飞行器能自己一直飞，靠的是"电源跟着机器走"：

- 红石块被推动后，下一 tick 在新的位置重新算电，于是另一台活塞被唤醒
- 伸出中的活塞在断电时缩回，形成交替

这一条是整套玩法的核心，实现时**先写一个能自持的引擎构型，用测试跑 20 tick 验证每 2 tick 前进 1 格**，
再用它做第一关。如果推演下来不稳定，退路是给"红石块"加一条"每 2 tick 翻转一次的脉冲"变体，
但先不预设，避免把简单问题复杂化。

## 7. 胜负与失败

- **过关**：机器所有零件都落在 `goal` 集合里（允许机器整体在终点区域内伸缩）
- **失败**：机器有任何一格出界；或者连续 20 tick 没有任何移动（卡死），界面提示可以"重置"
- 不限时

## 8. 三关

1. **起飞**：给一台拼好一半的机器，缺一块粘液块。目标是让它飞到右侧平台。教"粘液块粘住相邻方块"。
2. **越障**：中间一堵墙，终点在墙上的洞里。需要玩家调整机器高度，或者换成上下双活塞。
3. **停靠**：终点是一个凹槽，机器进去后伸出活塞当作刹车才不会飞过。教"伸出的活塞不可推动"。

后续可以加：拐弯（撞停后换向）、自动往返（两端各一套引擎）、载货（多带一个方块）。

- 入口：开始界面加「飞行器」，和「选关」并列

- 控制条：重置、暂停 / 继续、「下一刻」、开始飞行
- 机器飞出视口时相机自动跟随
