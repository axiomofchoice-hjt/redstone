# 关卡数据格式

关卡是纯数据，放在 `src/levels/` 下，一关一个文件。

## 关卡文件

```ts
export const level01: Level = {
  id: 'level-01',
  no: 1,
  name: '导线',
  brief: '用导线把 A 接到 B，让 B 始终等于 A。',  // 手机端「本关目标」页显示这段文字
  cols: 7,
  rows: 7,
  inputs: ['A'],        // 输入元件的字母
  outputs: ['B'],       // 输出元件的字母
  tools: ['wire'],      // 这关让玩家用的元件，不写表示全部
  cells,                // (Cell | null)[]，按行优先；A、B 预置并 locked
  solution,             // 可选，参考解；{ cells, state }，菜单里盖上去并恢复状态
  tests: [{
    // 第 0 tick 把 A 拉高，之后一直保持（信号不断）
    events: [{ tick: 0, values: { A: 1 } }],
    // 只要求第 0～20 tick 每 tick 的 B 都是 1，区间外不管
    checks: [{ from: 0, to: 20, outputs: { B: 1 } }],
  }],
}
```

## 字段

- `cells`：每个元件是 `{ type, dir?, id?, locked? }`，`dir` 为 `0..3`（上 / 右 / 下 / 左）。`locked: true` 的输入 / 输出是关卡预置的端口，玩家不能覆盖或删除，也不会出现在元件栏里。
- `brief`：这一关的目标说明，显示在手机端顶栏「本关目标」页；用 `\n` 分行，写清端口、判定规则和这一关的特殊限制。
- `tools`：限定这关可用哪些元件，没列出的在元件栏里变暗、点不了；不写这个字段就是全部可用（例如第一关只放开导线）。
- `solution`：可选的参考解，包含 `cells`（和地图一样是铺平数组）和 `state`（保存时的 `tick`、输入 / 输出取值、稀疏的每格通电状态）。写了的关卡菜单里「参考答案」可以点，没写的按钮灰掉。

## 测试用例

`events` 在设定的 tick 设置输入，设置后一直保持到下一次设置；`checks` 的 `[from, to]` 区间内每个 tick 都要符合期望，`to` 省略时只查 `from` 这一个 tick。

周期性信号用 `pairs` 检查（2-SAT 式）：同一条输出在两个时刻的取值只能落在列举的组合里。比如时钟要求间隔 2 tick 相反、间隔 4 tick 相同，就不用假定它从高还是从低开始；第十六关的 T 触发器初始是 0 还是 1 也不确定，跨过上升沿的两个时刻必须相反、没跨过必须相同：

```ts
pairs: [
  { output: 'Y', ticks: [10, 12], allow: [[0, 1], [1, 0]] },
  { output: 'Y', ticks: [10, 14], allow: [[0, 0], [1, 1]] },
]
```

### 测试怎么跑

测试是若干组，每组单独跑：每组的仿真都从玩家地图的副本开始（格子对象也逐个复制），组与组之间、以及测试与玩家的编辑状态互不影响。

游戏里点「测试」时，先把现场这块电路和它当前的仿真状态 fork 一份快照，每组测试都从这份快照起跑：编辑器之后接着跑、接着改都影响不到它，测试也动不到编辑器那份。改过电路不会清掉上一次显示的结果，只有再点一次「测试」才会重算。

关卡文件里的自动化测试（`runLevel(level)`）没有现场快照，从冷启动开始计拍；要用到启动后的稳定状态，就在测试数据里先写几拍 `A: 0` 当预热。第九至十九关都有类似的安排：第十一关先空跑几拍再给上升沿；第九、十、十二关把脉冲挪到第 15 tick、从第 10 tick 才开始检查，好让中继器串里可能残留的 1 先冲掉；第十四、十五关每次输入变化后都等 10 tick 再查；第十六关先落到 T=0、第十七关先落到 C=0，第一次上升沿都放在第 20 tick；第十六关整关用成对检查、只看跨不跨上升沿，第十七关的检查从变化后第 10 tick 开始；第十九关先落到 P=0、第一个脉冲放在第 20 tick，落沿后第 10 tick 才开始查，脉冲还高着的时候要求保持上一个结果。

测试数据里用到的输入都在第 0 tick 写全：`events` 只设置写到的输入，没写的会保持快照里的值——游戏里就是玩家拨过的那个开关。

所有关卡都有数据检查（每组测试必须在第 0 tick 设全输入），有参考解的关卡还有行为回归测试：都先把参考解的布局和保存的电路状态一起盖上、从这份状态开始跑——输入全开跑一阵再点「测试」也要全过，盖完参考答案直接点测试也要全过。

## 导出地图

菜单里的「导出地图」会把当前地图和导出时的电路状态下成 `level-XX-map.json`。

- `cells` 是稀疏对象，以行优先下标为 key，只记录有元件的格子（例如 7 列地图里的 `"22"` 表示第 3 行第 1 列），空格完全省略；要贴回关卡文件时按 `cols * rows` 展开成数组。
- `state` 记录当时的 `tick`、每个输入的 0 / 1、每个输出的 0 / 1，以及每格的通电状态 `powers`（bit0 是垂直通道、bit1 是水平通道）：`powers` 和 `cells` 一样是稀疏对象，只记录通电的格子，没电的格子省略。

各关参考解取的是哪个状态，见[各关设计说明](level-notes.md)。
